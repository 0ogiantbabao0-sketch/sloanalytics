# CSV中心のデータ収集・管理（Phase 1）

## 対応範囲

ホール基本情報、設置機種、機種別日次実績を、取得元ごとの列マッピングで登録します。UTF-8、BOM付きUTF-8、Shift_JIS/CP932、CSV・TSV・セミコロン区切りに対応。ExcelはCSVへ書き出してください。自動判定は推測を含むため、サンプル表示で文字化けと列を確認し、必要なら文字コード・区切りを選んで再解析します。

画面の登録順は「取得元設定 → ファイル解析 → マッピング → プレビュー・検証 → 確認した行を登録 → 完了結果」です。スマホではファイル選択を使えます。取得元ごとに保存・利用許可の根拠と確認日が必要です。参照候補の登録はCSV配布や利用許諾の存在を保証しません。

標準上限は20MB・100,000行・1レコード100,000バイト。サーバーの `IMPORT_MAX_BYTES`、`IMPORT_MAX_ROWS`、`IMPORT_MAX_RECORD_BYTES` で変更できます。アップロードはサーバーの一時ファイルへ段階的に書き、ハッシュを計算します。デコード・CSV解析はストリーム処理し、500行ずつステージングDBへ保存します。ブラウザへ返す行は最大100行です。検証・登録は単一Nodeプロセスの同期SQLiteトランザクションで、巨大な処理中はほかのリクエストが待つ場合があります。複数ワーカーのキューはPhase 3です。

## データ辞書

3種類共通で `data_kind`（`demo` / `real`）と `source_url` が必要です。CSVにない場合は確認画面の共通値で明示します。対応列がある場合は空欄も含めCSVの値を優先します。

| 種別           | 必須                                                                                           | 任意・条件付き                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| ホール基本情報 | hall_id、hall_name、address、lat、lng                                                          | hall_external_id、official_url、hours、lottery_time                                                  |
| 設置機種       | 登録済みホールのID／名前／外部ID、機種のID／名前／外部ID、units、valid_from または survey_date | valid_to、manufacturer、model、machine_external_id                                                   |
| 機種別日次実績 | 登録済みホール、機種、date、units、avg_diff または total_diff                                  | positive_units、positive_rate、games、payout_rate、win_rate、points、published_at、source_updated_at |

- `avg_diff` は掲載平均、`total_diff` は掲載合計。平均しかない場合、総差枚はNULLです。平均×台数を総差枚として登録しません。
- 両方ある場合、総差枚÷台数と掲載平均の差を検証します。初期の丸め許容は0.5枚。定義に合わないものは要確認です。
- 平均の集約は対象台数で加重します。集約対象に総差枚未取得の行があれば、期間総差枚も「未取得」と表示します。
- `games` は1台平均。単に「G数」「差枚」とだけ書かれた曖昧な列は自動対応させません。意味を確認して割り当てます。
- プラス台率しかない場合、プラス台数を逆算しません。現段階のランキングのプラス台率は取得済みプラス台数を使います。率だけの値は一次記録に保存します。
- 勝率・出玉率・差枚相当ポイントは別項目です。差枚・プラス台率に変換しません。
- 日付は営業日として保存。タイムゾーンなしの公開日時 `YYYY-MM-DD HH:mm[:ss]` は日本時間として解釈し、UTCのISO表現で保存します。営業日は未来日を拒否します。
- 空欄・不明・N/AはNULL。必須列なら登録不可です。数値・日付の正規化内容はプレビューに表示します。
- 設置の終了日がないと継続有効になるため警告します。日次実績から作る観測設置はその営業日だけ有効です。

テンプレートは管理画面または `public/samples/{halls,installations,results}-template.csv`。`phase1-demo.zip` は架空店舗の3種類のCSVです。必ずデモモードへ登録してください。

## 名寄せ・重複・競合

名前のNFKC正規化、空白正規化、既存の明示的な機種別名を使います。似た名前を自動的に同じものとは扱いません。新規ホールは基本情報CSVで先に登録し、座標は推測しません。別表記は管理画面の「CSV用の店舗・機種別名を登録」で、対応するIDと根拠を登録してください。住所・座標が異なる既存店舗や型式の異なる機種は要確認です。

元ファイル名、元バイト列のSHA-256、解析形式、マッピング、各行の原文・正規化値・確認結果・取込日時を保存します。同じ出典・種別・レコードキー・内容の再取込みは重複として除外します。ファイル内の同一キーの2行目以降は登録不可。同じファイルの登録ボタン再実行も登録済みの結果を返します。

初回の検証済み出典を代表値として採用し、同じ採用出典の訂正のみ更新します。他の出典は別記録として保持し、上書きしません。優先度は候補情報として保存しますが、優先度だけで代表値を切り替えません。新CSV基盤の競合解決・取り消しUIはPhase 2です。数値または定義が競合する実績は期待度から除外します。従来画面の採用先切替は代表値を変更しますが、新しい採点エンジンの競合解消認定には未接続です。競合の残る日は引き続き採点対象外です。

検証の正常行だけを登録でき、警告行は利用者がチェックを入れた場合に登録します。重複・要確認・登録不可は除外。登録直前にも権限と値を再検証し、行ごとの失敗はSQLite SAVEPOINTで取り消します。正常行が残る登録結果も件数で報告します。

## 履歴・修正・トラブル対応

管理画面の履歴から行別結果とエラーCSVを確認します。エラーCSVにはレコード番号・原値・状態・理由が含まれます。CSVの数式解釈を防ぐため危険な先頭文字には引用用の文字を加えることがあり、修正時は確認してください。元ファイルを直して再アップロードする方法を推奨します。

保存マッピングは取得元とCSV種別に紐付きます。ヘッダーの名前・順序が変わったら自動適用せず、再確認を表示します。解析に失敗したファイルも履歴に残します（ファイルサイズ超過など、保存完了前の失敗は履歴に残らない場合があります）。

登録後はカタログと検索を再読込みし、DBの最新値で計算します。DB上の採用値を削除・訂正すれば次の検索で反映され、古い集計キャッシュを返しません。現在は指定した日付範囲を絞って計算し、永続の増分集計キャッシュは未導入です。

## 今回の対象外

台番・イベントCSV、貼り付けステップ、Excel直接読込み、網羅性分析、取り込み単位のロールバック、競合採用切替の新UI、ジョブキュー、スケジューラー、通知は後続Phaseです。自動取得の許可状態・方法は設定できますが、この管理画面からの自動実行は未接続です。許諾なしの実行はサーバーで拒否し、許諾ありでもPhase 3の接続待ちと表示します。既存の契約済みHTTPS CSVアダプタは従来の固定形式向けで、新しい列マッピングの自動実行にはまだ接続していません。
