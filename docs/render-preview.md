# スマホ用の共有URL（Render）

`render.yaml` は無料Web Serviceでデモを確認するための設定です。公開URLの発行には、Renderアカウントと対象GitHubリポジトリへの接続が必要です。設定ファイルを作成しただけでは公開されません。

## 公開手順

1. スマホのブラウザで [Render](https://dashboard.render.com/) にログインする。
2. 最新のモバイルUI・出典統合の変更と `render.yaml` を含む公開用ブランチは `preview/mobile-tabs`。このブランチをGitHubへ反映してから接続する。現在のクラウド作業フォルダーだけにある変更はRenderから参照できない。
3. Renderで「New → Blueprint」から `0ogiantbabao0-sketch/sloanalytics` を接続し、ブランチを `preview/mobile-tabs`、Blueprintのパスを `render.yaml` にする。GitHubの認可画面が表示されたら対象リポジトリへのアクセスを設定する。
4. サービスがFreeプランであることを確認し、Blueprintを作成する。この設定は有料ディスクや有料DBを作成しない。
5. ビルドと起動が完了しLiveになったら、サービス画面に表示されたHTTPS URLをスマホで開く。URLはRenderが発行する実際の値を使用する。

DockerfileはNode.js 24でビルドし、起動時にデモDBを初期化してポート3000で待ち受けます。`/api/health` でDBへの接続を確認します。自動デプロイは無効にしているため、以後の更新時には対象コミットを確認して手動デプロイします。

## デモの確認

「デモ」を選び、対象日を `2026-10-10` にして分析します。下部の5タブ、比較追加、保存、縦横回転時の操作は [実機確認手順](mobile-testing.md) に沿って確認してください。

無料インスタンスは停止・再作成されることがあり、初回表示に時間がかかる場合があります。SQLiteの永続ディスクは付けていません。サーバー側データの保存を必要とする運用には [永続ディスク付き構成](operations.md) を使ってください。

共有URLはログイン不要で閲覧できます。この設定では管理トークンと外部取得設定を空にしており、管理APIの書込みと外部データ取得は無効です。既存のローカルDB・秘密情報はDockerイメージへ含めず、公開先では合成データを生成します。

## 検証状況

アプリの本番ビルドとモバイル幅でのブラウザ操作はクラウド開発環境で確認済みです。Render上でのビルド・起動、外部URLからのアクセス、スマホ実機での操作はデプロイ後に確認が必要です。
