# Codex開発指示書：SLOT ANALYTICS

## 1. プロジェクト概要

日本全国のパチスロホールについて、過去の出玉実績・設置機種・イベント情報・曜日・特定日・連休傾向を分析し、条件に合ったおすすめホールと機種をランキング形式で提示するWebアプリ「SLOT ANALYTICS」を新規開発する。

単なる出玉情報表示サイトではなく、**「いつ・どのホールで・どの機種を狙うか」を客観的なデータと根拠で比較できる分析ツール**とする。

スマートフォン（特にiPhone）で日常的に利用しやすい操作性と、PCでの詳細分析機能を両立する。

実際に動作するアプリを実装し、ソースコード・データベース・テスト・起動方法・運用方法まで提供すること。

## 2. 技術・設計方針

推奨技術：

- TypeScript
- Next.js / React
- Tailwind CSS
- SQLite（初期MVP）またはPostgreSQL（本番運用）
- Prismaまたは同等のORM
- Leaflet / OpenStreetMapによる地図表示
- Rechartsなどによるグラフ
- 日本の祝日・振替休日・国民の休日に対応したカレンダーライブラリ
- 定期更新処理とCSVインポート機能

既存プロジェクトがあれば調査して活用する。なければ新規作成する。

画面デザインは白ベース、ダークネイビーの文字、青を主要アクセント、緑をプラス実績に使用した、洗練されたデータ分析ダッシュボードとする。

日本語UI、iPhone Safari対応、レスポンシブデザインを必須とする。

## 3. エリア検索機能

検索の中心地を自由に指定し、そこから半径○km以内のホールを抽出する。

中心地の指定方法：

- 駅名
- 住所
- 施設名
- 地図上での地点選択
- 登録済み地点

初期プリセット：

- 長岡京駅
- 京都駅
- 梅田駅
- 高槻駅

検索半径：

- 5〜100km
- スライダー操作
- 数値直接入力
- 5km刻みのプリセット

検索範囲は緯度経度から計算する直線距離（ハバーサイン距離）とし、画面にも明記する。

移動手段：

- 電車
- 車
- 両方

移動手段は検索条件として保存する。経路サービスが利用可能な場合は所要時間・走行距離・アクセス情報も表示する。経路データを取得できない場合は推測値を表示しない。

検索結果のホールを地図上に表示し、ランキングと連動させる。

初期対象は京都・大阪・兵庫・滋賀とするが、全国対応可能な設計とする。

## 4. 日付・条件検索

次の条件を組み合わせて検索できるようにする。

### 対象日
- 今日
- 明日
- カレンダーから任意の日付
- 任意の日付範囲

### 特定日
- 0〜9のつく日
- 10日、11日、21日など特定の日付
- 毎月の旧イベント日
- ゾロ目の日
- 指定ホールの特定日

### 曜日
- 月曜日〜日曜日
- 平日
- 土曜日
- 日曜日
- 土日
- 土日祝

### 連休
- 3連休以上
- 4連休以上
- 5連休以上
- 連休初日
- 連休中日
- 連休最終日
- 連休の何日目か

日本の法定祝日、振替休日、国民の休日を正確に判定する。

例えば2026年10月10日〜12日は3連休と認識し、初日・中日・最終日を区別する。

### イベント
- イベント掲載あり
- 来店予定あり
- 取材予定あり
- 旧特定日
- イベント種類
- イベント名・出演者

イベントの告知と実際の開催を別データとして管理する。

複数条件はAND/ORで組み合わせ可能とする。

### 分析対象期間
- 過去30日
- 過去90日
- 過去180日
- 過去365日
- 任意期間
- 前年同時期との比較

## 5. 機種検索と3つのランキングモード

### モードA：おまかせ（機種指定なし）

最重要機能。

機種を指定しない場合、検索範囲内のホールと設置機種の組み合わせをすべて評価し、**「おすすめホール × おすすめ機種」**のランキングを表示する。

表示例：

1位：ホールA／カバネリ
2位：ホールB／マイジャグラーV
3位：ホールA／北斗の拳

同じ店舗が複数回登場してもよい。

「各ホールの最上位機種のみを表示する」切り替えも設ける。

### モードB：機種指定

ユーザーが特定の機種を指定する。

例：カバネリを指定した場合、その機種について評価の高いホールをランキング表示する。

複数機種の指定にも対応する。

機種の検索候補はデータベースに登録された全機種から取得し、検索・複数選択できる。

初期注目機種：

- L カバネリ 海門決戦
- マイジャグラーV
- スマスロ北斗の拳

これらだけに限定しない。

### モードC：ホール指定

特定のホールを選ぶと、そのホールのおすすめ機種ランキングを表示する。

指定された曜日、特定日、連休、分析期間に対応した機種実績から順位付けする。

機種名の表記ゆれ・略称を統一し、同一機種を正しく集計できるようにする。

## 7. データ収集方法と制約

データ取得は次の優先順位とする。

1. 正式なAPI
2. 利用許諾のある公開データ
3. 許可されたCSV・ファイルインポート
4. 管理画面からの手動登録
5. 利用規約・アクセス条件に適合するその他の取得方法

公式店舗、P-WORLD等の設置情報、出玉集計サイト、取材サイトなどは候補として調査する。ただし、利用規約・著作権・転載制限・アクセス条件を確認してから連携する。

スクレイピングが禁止されているサイトに対して、禁止された自動取得やアクセス制限回避を行わない。

データソースごとに独立した取得アダプタを実装する。

取得できない情報は「未取得」「データ不足」と表示し、値を推測・捏造しない。

実データとデモデータは厳密に分離する。

初期開発時にはCSVインポート機能と、サンプルCSVを必ず提供する。

## 8. ランキング計算ロジック

ランキングは平均差枚のみで決めない。

以下の指標を組み合わせる。

- 該当条件の平均差枚
- 同機種の通常日の平均差枚との差
- プラス台率
- 稼働ゲーム数
- 対象台数
- 該当条件のサンプル日数
- 実績の安定性
- 直近実績
- 曜日一致
- 日付条件一致
- 連休条件一致
- 旧特定日一致
- イベント情報

総合スコアを0〜100点で算出する。

ただし、カバネリ・ジャグラーなど出玉特性が異なる機種の平均差枚をそのまま比較しない。同機種の通常ベースラインからの変化などで標準化する。

少数の好成績だけで極端な高得点にならないよう、ベイズ縮小や信頼区間など、データ数に応じた補正を採用する。

以下を別々に表示する。

- 総合おすすめスコア
- データの信頼度・充足率
- サンプル日数
- 取得データの最終更新日時

データ不足の項目は採点方法を明示する。情報が極端に少ないホール・機種は評価保留にできるようにする。

イベントがあるという事実だけで高設定と断定しない。

ランキングの順位は期待収支や勝率の保証ではなく、過去実績に基づいた相対評価として表示する。

## 9. ランキング根拠表示

各ランキング項目には「なぜ上位なのか」を説明する。

例：

- 過去の0のつく日8回中6回で平均差枚プラス
- 同機種の通常日より平均差枚が400枚高い
- 直近3回の該当日でプラス台率が上昇
- 土曜日の平均稼働ゲーム数が高い
- 該当データが2日分のみで信頼度は低い

文章は実際に計算・取得したデータから生成する。

存在しない実績や根拠を表示しない。

集計条件と対象日一覧を詳細画面で確認できるようにする。

## 21. 実装順序

**Phase 1：基本アプリ**

画面、検索条件、DB、CSVインポート、実績集計、ランキング、ホール詳細、機種詳細、地図を実装する。

**Phase 2：高度分析**

台番別分析、連休詳細分析、条件横断比較、スコア改善、抽選データ、比較機能を実装する。

**Phase 3：運用自動化**

利用許可を確認済みの取得元との連携、定期更新、失敗監視、デプロイ、データ品質管理を実装する。

ただしPhase 1の時点で、CSVなどで実データを投入すれば検索とランキングが実用可能な状態とする。

## 22. 開発上の必須原則

- 動作しないボタンやダミー検索を完成品としない。
- デモデータと実データを明確に区別する。
- サンプルのランキングを実際の推奨順位として表示しない。
- 未取得データを推測して補完しない。
- 収集元の利用条件を守る。
- 出典とデータ更新日時を確認できるようにする。
- ランキング根拠を透明化する。
- 設定投入や収支を保証する表現をしない。
- ユーザーの検索条件を正確に反映する。
- 仕様の実装済み・未実装・制約事項を最後に明確に報告する。

## 23. 完了条件

以下を実際に操作できること。

**操作例A：**
中心地「長岡京駅」、半径30km、対象日「2026年10月10日」、機種指定「カバネリ」とすると、範囲内の対応ホールが検索され、根拠付きで順位表示される。

**操作例B：**
同じ条件で機種指定を解除すると、すべての収録機種の中から「おすすめホール×機種」をランキング表示する。

**操作例C：**
ホールを指定し「11のつく日」「過去180日」で検索すると、そのホールにおける機種別の過去実績が比較できる。

**操作例D：**

**操作例E：**
2店舗を選択すると、同一日付条件・同一機種の平均差枚、プラス率、サンプル数、信頼度を横並び比較できる。
