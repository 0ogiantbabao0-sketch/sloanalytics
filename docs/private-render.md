# Render継続・本人用認証と永続保存

## 現在の公開版との違い

この実装はプロダクション起動時に本人用認証を既定で有効にします。認証設定が不足した場合は公開読取りへフォールバックせずログインを拒否します。ヘルスチェックとログイン以外の画面・APIは認証必須です。

既存のRenderサービスのEnvironmentで、次を設定してから最新版を手動デプロイしてください。値はチャットやGitに記載せずRenderへ直接入力します。

| 変数                 | 設定                                                                        |
| -------------------- | --------------------------------------------------------------------------- |
| PRIVATE_ACCESS       | `true`                                                                      |
| OWNER_PASSWORD       | 本人だけが知る長いランダムなパスワード（16文字以上）                        |
| OWNER_SESSION_SECRET | パスワードと異なるランダムな秘密値（32文字以上）                            |
| DATA_DIR             | 永続ディスクを付ける場合 `/var/data/slot-analytics`                         |
| ADMIN_IMPORT_TOKEN   | 本人用ログインを使う場合は不要。従来APIの管理トークンとして使う場合だけ設定 |

ログイン後は12時間有効な署名付きHttpOnly・SameSite=Strict・本番Secure Cookieを使います。パスワードまたは署名秘密値を変更すると既存セッションも無効になります。管理画面からログアウトできます。5回の認証失敗で5分間待機（単一プロセス内、再起動でリセット）します。書込みリクエストは同一Originを要求します。Cookie・パスワードはlocalStorageへ保存しません。

開発サーバーでは認証は既定で無効です。開発でも確認する場合は `PRIVATE_ACCESS=true` と2つの秘密値を設定します。プロダクションで `PRIVATE_ACCESS=false` を指定すると公開モードになるため、実データの私的利用時には指定しないでください。

## 永続保存と費用

現在のRender Freeと一時SQLiteでは、サービスの再作成でDB・原CSVが失われます。実データ運用を開始する前に、永続ディスク対応の有料インスタンスとディスクが必要です。代替は外部PostgreSQL＋ファイル保管ですが、その移行は今回行っていません。

この変更で有料サービスの作成やプラン変更は行いません。Renderの選択画面に表示される現在の月額料金を確認し、利用者が選択してから設定します。今回の `render.yaml` は無料デモ構成を維持し、有料プランを自動追加しません。

永続ディスクを使う場合の設定案：

- 対象：既存の `slot-analytics-preview` サービス。
- 単一インスタンス。
- ディスクのマウント先：`/var/data`。
- DATA_DIR：`/var/data/slot-analytics`。
- この配下に `demo.sqlite`、`real.sqlite`、`imports/demo`、`imports/real` を保存。
- ディスクの書込み権限がコンテナの `node` ユーザーにあることを起動ログで確認する。

新しい空の保存先では合成データを生成し、実DBは空で開始します。既存の実データがある場合は先にバックアップし、新しいディスクへ復元してください。

## バックアップ・復旧

DBだけでなく、`imports` 以下の原CSVも一緒に保全してください。元ファイルには利用許諾されたデータが含まれるため公開ディレクトリやGitへ置きません。

整合した完全バックアップはアプリと取込処理を停止した状態で、SQLiteのバックアップ機能と原CSVのコピーを使います。既存の [運用手順](operations.md) のSQLiteバックアップ・integrity_checkに従い、`imports` のコピーも同じバックアップへ保存します。DBのWALファイルを無視した稼働中の単純コピーは避けます。

復旧も停止中に行い、復旧前のDB・CSVを退避し、バックアップのDBと原CSVを対応するDATA_DIRへ戻してから起動します。別のDATA_DIRへ復旧すると、`import_files.path` の保存済み絶対パスも新しい位置へ移す必要があるため、通常は同じDATA_DIRで復旧します。将来のインポート単位取り消しとは別の操作です。

## デプロイ後の確認

1. 未ログインでトップがログイン画面へ移動し、`/api/catalog?mode=real` が401になる。
2. ログイン後に管理画面を開ける。秘密値が画面・JavaScript・URLへ含まれない。
3. DEMOサンプル3種類をデモDBへ登録して検索・内訳を確認する。
4. サービスを再起動し、永続ディスク上の登録データと原CSVが残ることを確認する。
5. ログアウトするとAPIを読めなくなる。

公開URLへの新機能の反映と永続ディスクの再起動確認は、利用者のRender設定後に別途確認します。実サイトからの自動取得・実データ投入はこの開発では行いません。
