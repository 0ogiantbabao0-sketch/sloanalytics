# SLOT ANALYTICS

日本語のホール × 機種分析ダッシュボード。**動作するMVP**です。Next.js 15 / React 19 / TypeScript / Node.js 24 / SQLite / Leaflet / Recharts を使用します。

実店舗の実績は収集・検証していません。初期画面は、架空6店舗・4機種・2025-01-01〜2026-10-09の合成データです。実データ用DBには実績を投入しません。

## 起動

```sh
cd /workspace/sloanalytics
npm ci
npm run db:setup
npm run dev
```

Node.js **24系**が必要です。標準の `node:sqlite` を使うため、DBサーバー・Docker・外部キーは不要です。開発ポートは3000です。プロジェクトを別の場所に置いた場合は、そのディレクトリから実行します。

スマホ実機から接続する手順は [スマホでの動作確認](docs/mobile-testing.md) を参照してください。

`db:setup` は再実行可能で、既存データを削除しません。`data/demo.sqlite` と `data/real.sqlite` を作成します。両DBには機種名・略称マスタだけを共通登録します。ソースのスキーマは [src/lib/schema.sql](src/lib/schema.sql) です。DBファイルはGit管理外です。

CSV管理画面を使う場合は `.env.example` を `.env.local` にコピーし、`ADMIN_IMPORT_TOKEN` に十分長いランダムな値を設定してサーバーを再起動してください。管理画面へ同じ値を入力します。未設定時は取込APIが503を返し、書込みを無効化します。トークンはブラウザへ配布・保存しません。設定ファイルをGitへ追加しないでください。

```sh
npm test                  # カレンダー、集計、順位補正、CSV、検索の自動テスト
npm run typecheck
npm run build
npm start                 # 本番モード（build後）
```

## 操作例

画面上部でデモ／実データを切り替えます。「この条件で分析する」で検索条件が反映されます。並び替え・最上位機種のみ表示・地図の中心点変更は即時反映です。

- **A** 長岡京駅・30km・2026-10-10 → 機種指定 → 「カバネリ」で検索して選択 → 分析。
- **B** おまかせへ切り替え → 分析。収録された全機種を店舗横断で比較。
- **C** ホール指定 → デモ長岡京パーク → 過去180日 → 詳細条件の毎月の特定日を11日 → 分析。
- **D** 機種指定「マイジャグラーV」→ 3連休以上・最終日 → 分析。その他の条件は解除。
- **E** ランキングの「比較に追加」で異なる2店舗を選び、比較画面で同じ機種を指定。

検索に該当する実績がなければ「データ不足」。実績が3日未満、または同機種の通常日が3日未満ならスコアは「評価保留」です。将来の設置台数や所要時間を推測しません。

## 検索・計算の定義

- 対象日は予測基準日です。標準の集計期間は**対象日の前日から過去N日**。範囲指定時も開始日を基準にし、期間中のイベントと設置情報を照会します。各対象日について別々の予測スコアを生成する機能ではありません。
- 曜日・末尾・特定日・連休・イベントは**過去の営業日**に適用。対象日の曜日を自動適用しません。土曜比較をしたい場合は土曜日を選択します。
- `0〜9のつく日` は日付末尾。`11のつく日` は指示書の操作例Cに合わせ**毎月11日**として扱います。11・21・31日をまとめる場合は「1のつく日」。
- ゾロ目は11日・22日、または月日一致（10/10など）。UIに定義を表示しています。
- 曜日グループの平日は祝日を除く月〜金。連休は土日と日本の法定祝日が連続する期間。正月・お盆の独自休業日は含めません。
- 祝日ライブラリは `@holiday-jp/holiday_jp`。1970〜2050年を扱います。将来の法改正や祝日変更に合わせ依存データを更新してください。
- 条件グループ間をAND/OR、同一グループの複数選択をORで評価。連休の長さ・位置・何日目は一体の条件としてAND。
- 検索半径はハバーサイン式の直線距離。移動手段は保存しますが経路・時間を推測しません。
- 同機種の通常日は、収録全店舗の「平日・非祝日・旧特定日でない・非イベント日」。基準比較は対象期間内の同機種に限ります。
- 平均差枚とプラス台率は台数で加重。収録機種だけの合計を店舗全台の実績と表示しません。
- 通常日からの標準化改善50%、プラス台率15%、ゲーム数10%、安定性10%、直近3日とその前3日の差10%、鮮度5%。指標を−1〜1に変換し、欠損分の重みを除外・再配分。
- `score = clamp(50 + 50 * n/(n+8) * weightedSignals, 0, 100)`。ベイズ的な中立値への縮小で、少数の好成績を抑制。厳密な事後確率や勝率ではありません。
- 信頼度はサンプル日数、指標充足率、観測台数、鮮度から独立計算。イベントの存在だけでは加点しません。
- 根拠文・対象日一覧・更新日時・出典は計算値から生成します。

## データ投入

詳細は [docs/data-import.md](docs/data-import.md)。管理画面からダウンロードできるファイル：

- [デモ用サンプルCSV](public/samples/demo-results.csv)：合成データの取込練習用。
- [実データ用テンプレート](public/samples/real-template.csv)：ヘッダーのみ。許諾と値を検証して記入。

UTF-8、2MB／10,000行以内。`data_kind` と取込先が一致しないCSVは拒否します。書込みは全件を1トランザクションで処理します。同一ファイル内の重複は拒否し、採用中の出典の訂正だけをランキングへ反映します。別出典は個別に保存し、管理画面で採用先を選べます。失敗履歴はロールバック後も残ります。

正式要件の原文は [docs/requirements.md](docs/requirements.md) に保存しています。

## ブラウザ検証

```sh
npx playwright install --with-deps chromium webkit
npm run test:e2e
```

既存のChromiumがある環境では：

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e -- --project=desktop --project=mobile-chromium
```

テストは `/tmp/slot-e2e-*` に独立DBを作成し、一時管理トークンと3100番ポートを使います。開発用DBを変更しません。iPhone幅のChromium検証とWebKit検証は別プロジェクトです。WebKitが未導入なら、Chromiumの成功をSafari検証済みとは扱わないでください。

現在の環境の検証結果と制約は [docs/verification.md](docs/verification.md) を参照してください。

## 構成・運用

- `src/lib/schema.sql`：DB基本スキーマ。`migrations.ts` でバージョン2へ追加テーブルを移行。
- `src/lib/analytics.ts`, `metrics.ts`, `calendar.ts`：検索・スコア・計算。
- `src/lib/importer.ts`, `adapters.ts`：入力検証、CSV取込、許可済みHTTP取得。
- `src/app/api/`：読み取りAPI、保護されたインポートAPI。
- `src/components/`：日本語レスポンシブUI。
- `scripts/setup.ts`：再現可能な合成データとDB初期化。
- `tests/`：ロジック・SQLite統合・ブラウザ操作テスト。

起動・更新・バックアップ・デプロイは [docs/operations.md](docs/operations.md)、データソースと利用制約は [docs/data-sources.md](docs/data-sources.md) を参照。

クラウドタスク自体が分離環境です。既存チェックアウトで開発し、明示的な依頼がない限り追加のGit worktreeは作成しません。

## 複数出典の統合・競合調査（追加開発）

管理画面に、許可のある日別機種実績の手動登録、取得元別の店舗・機種名寄せ、出典別の実績比較と採用切替を追加しました。出典・取得日・公開日・提供元更新日・集計定義と取得時点のスナップショットを保存し、別サイトの値を加算・自動上書きしません。CSV v2テンプレートも管理画面から取得できます。従来CSVは利用可能です。

自動更新は `PERMITTED_SOURCES_FILE` で複数の契約済みHTTPS CSVを構成します。URLだけの旧設定では開始せず、自動取得・再配布の許諾、確認日、有効期限、取得間隔を検査します。HTMLスクレイピングや候補サイトの自動連携は実装・有効化していません。

- [8サイトの調査記録](docs/competitive-research.md)：現環境の通信制限により本文・規約・API等は未確認。分類は依頼に基づくもので、調査済みの掲載内容ではありません。
- [統合設計・アダプタ設定・DB移行](docs/source-integration.md)
- [CSV v2・手動登録仕様](docs/data-import.md)

設計判断：名寄せは取得元ごとの明示登録とし、機種の世代や店舗の支店名を曖昧一致で統合しません。異なる集計定義は変換根拠が確認できるまで取り込みません。初回出典を採用し、別出典への切替は管理者が比較して実行します。ランキングの計算式や他サイトの文章・デザインには変更・転用を行っていません。

## スマートフォンのタブ操作

幅760px以下では「探す・比較・台番・保存・管理」の5タブを画面下部に固定表示します。選択中のタブを色と背景で示し、ホール・機種詳細では「探す」の選択表示を維持します。適用済みの検索条件と比較候補を保持したまま画面を移動できます。

現在のタブをもう一度タップすると先頭へ戻ります。比較タブには選択した店舗数を表示します。タップ領域、読み上げ用の画面名・選択状態、iPhoneのセーフエリア、比較ボタンと本文の下端余白に対応しています。PCでは引き続きサイドメニューを表示します。
